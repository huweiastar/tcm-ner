# 数据集入门指南：从一行标注读懂中医药 NER

这份指南专门解释 `data/medical.train`、`data/medical.dev` 和
`data/medical.test`。先读懂它，再运行训练，会更容易理解模型究竟在学什么。

## 1. 这个数据集要解决什么问题

命名实体识别（Named Entity Recognition，NER）的目标是：给定一段文字，找出
其中有特定意义的词语，并判断它属于哪一种类别。

例如，输入文本：

```text
投活络效灵丹加味：当归、丹参各１５ｇ
```

人工标注希望模型找到：

| 原文中的完整词 | 类别 | 通俗理解 |
| --- | --- | --- |
| 活络效灵丹 | 方剂 | 一个中药处方或方名 |
| 当归 | 中药 | 一味中药 |
| 丹参 | 中药 | 一味中药 |

因此，本作业不是让模型回答医学问题，也不是生成诊断结论，而是让模型从已有
文字中**圈出实体词并分类**。

## 2. 三个文件分别做什么

| 原始文件 | 训练中的名称 | 用途 | 转换后的样本数 |
| --- | --- | --- | ---: |
| `data/medical.train` | train | 模型真正用来学习的数据 | 5259 |
| `data/medical.dev` | validation | 训练过程中观察是否学好、是否过拟合 | 657 |
| `data/medical.test` | test | 训练结束后一次性报告最终 F1 | 658 |

测试集不应该混入训练过程，否则最终成绩会失真。

数据中的文本可能是一段病例描述、论文标题、处方片段或临床疗效描述，不一定
都是完整语法句子。这不影响 NER：模型只需识别片段中出现的实体。

## 3. 原始文件为什么“一行只有一个字”

原始文件采用字符级 `BIO` 标注格式：

```text
投 O
活 B-方剂
络 I-方剂
效 I-方剂
灵 I-方剂
丹 I-方剂
加 O
味 O
： O
当 B-中药
归 I-中药
、 O
丹 B-中药
参 I-中药
```

阅读方法是：

| 第一列 | 第二列 | 含义 |
| --- | --- | --- |
| `投` | `O` | “投”不属于任何需要抽取的实体 |
| `活` | `B-方剂` | 一个“方剂”实体从“活”这个字开始 |
| `络`、`效`、`灵`、`丹` | `I-方剂` | 继续属于刚才开始的同一个方剂实体 |
| `当` | `B-中药` | 一个新的“中药”实体从“当”开始 |
| `归` | `I-中药` | 和“当”合成完整实体“当归” |

把第一列连续拼起来，还原后的原文是：

```text
投活络效灵丹加味：当归、丹参
```

把 `B-` 开头的位置和后续同类 `I-` 拼起来，还原出的完整实体是：

```json
[
  {"entity": "活络效灵丹", "type": "方剂"},
  {"entity": "当归", "type": "中药"},
  {"entity": "丹参", "type": "中药"}
]
```

原始文件中的**空行**表示一个文本样本结束，下一行开始属于新样本。它不是实体
标签的一部分。

## 4. BIO 三种标签是什么意思

| 标记 | 英文含义 | 小白理解 | 例子 |
| --- | --- | --- | --- |
| `B-类别` | Begin | 这个字是一个实体词的第一个字 | `黄 B-中医诊断` |
| `I-类别` | Inside | 这个字继续属于前面同类别的实体词 | `疸 I-中医诊断` |
| `O` | Outside | 这个字不属于任何被标注实体 | `稍 O`、`退 O` |

以测试集片段为例：

```text
药 O
进 O
１ O
０ O
帖 O
， O
黄 B-中医诊断
疸 I-中医诊断
稍 O
退 O
```

它恢复为文本 `药进１０帖，黄疸稍退`，其中只有 `黄疸` 被标为 `中医诊断`。

再看一个容易理解词边界的例子：

```text
疏 B-中医治则
肝 I-中医治则
行 I-中医治则
气 I-中医治则
， O
调 B-中医治则
神 I-中医治则
解 I-中医治则
郁 I-中医治则
```

虽然两个词类别都为 `中医治则`，但第二个词重新以 `B-中医治则` 开头，所以它们
是两个实体：`疏肝行气` 和 `调神解郁`，不能错误合并为一个长词。

## 5. 十种实体类别怎么理解

下表的示例均来自本项目标注数据。应当以数据集给出的标签为训练标准；医学上
可能存在细分方式差异，但做本任务时不能凭个人理解随意改标签。

| 实体类别 | 数据集中要找的内容 | 数据中的真实示例 |
| --- | --- | --- |
| `中医治则` | 中医治疗原则、治法思想 | `疏肝理气`、`清热解毒`、`安神和胃` |
| `中医治疗` | 中医具体治疗手段或治疗制剂 | `针灸`、`热敏灸`、`复方丁香开胃贴` |
| `中医证候` | 中医辨证得到的证型、证候 | `肝郁脾虚`、`寒湿困脾`、`脾胃湿热` |
| `中医诊断` | 中医疾病或病名诊断 | `泄泻`、`阳黄`、`水鼓` |
| `中药` | 单味药材或中药名称 | `当归`、`丹参`、`三七` |
| `临床表现` | 症状、体征等表现 | `口苦`、`咯血`、`腹痛` |
| `其他治疗` | 不归入中医或西药类别的辅助干预 | `生活方式干预`、`心理疏导`、`日光浴` |
| `方剂` | 中医复方名称、方名 | `活络效灵丹`、`五苓散`、`地黄汤` |
| `西医治疗` | 西药或现代医学治疗名称 | `法莫替丁`、`莫沙必利`、`辛伐他汀` |
| `西医诊断` | 西医疾病名称或诊断 | `肺结核`、`功能性消化不良`、`缩窄性心包炎` |

一个常见疑问是：`方剂` 与 `中医治疗` 为什么看起来有时相近？这是实体标注任务
的正常现象。例如方名通常标为 `方剂`，而 `针灸`、`推拿` 或外治制剂可被标为
`中医治疗`。训练和评价时，应遵循数据集现有定义，而不是在预处理时重新分类。

## 6. 从原始标注到模型训练样本

原始 BIO 数据适合标注和传统分类模型，但生成式大模型更适合看到“问题 + 答案”。
因此项目将每个文本样本转换为 SFT 格式。

原始片段：

```text
现 O
头 O
昏 O
口 B-临床表现
苦 I-临床表现
```

恢复出的原文与答案：

```json
{
  "text": "现头昏口苦",
  "gold_entities": [
    {"entity": "口苦", "type": "临床表现", "start": 3, "end": 5}
  ]
}
```

给模型训练时，将它包装成：

```text
用户：请识别下列文本中的中医药相关实体：
现头昏口苦

助手：[{"entity":"口苦","type":"临床表现","start":3,"end":5}]
```

其中字符位置按照 Python 切片习惯计算：

```text
位置： 0  1  2  3  4
字符： 现 头 昏 口 苦
```

`口苦` 从位置 `3` 开始，到位置 `5` 之前结束，因此
`text[3:5] == "口苦"`。

## 7. 为什么最终评价不是单字 F1

NER 的目标是找到完整词。例如金标准是：

```text
腹痛 -> 临床表现
```

模型只预测：

```text
痛 -> 临床表现
```

它虽然猜中了一个字，却没有正确找到完整实体边界。在本项目中，这条预测记为
错误，不会获得部分分数。

评价脚本要求下面四项全部一致才算正确：

| 检查项 | 示例 |
| --- | --- |
| 实体类别 | `临床表现` |
| 实体开始位置 | `start=0` |
| 实体结束位置 | `end=2` |
| 实体完整文本 | `entity="腹痛"` |

这就是作业要求的“词的 F1 score”，而不是逐个字的标签准确率。

## 8. 如何亲手查看数据

直接打开任一原始文件，会看到字符级 BIO 格式：

```bash
sed -n '1,80p' data/medical.dev
```

运行预处理后，再查看更容易阅读的完整文本与实体 JSON：

```bash
python prepare_sft_data.py --data_dir data --output_dir processed_data
sed -n '1,2p' processed_data/validation.jsonl
```

也可以打开项目提供的 Notebook，在“读取原始 BIO 标注”和“转换为 SFT 数据”
两节中逐步查看同一个样本如何从单字标签变成可训练答案。
